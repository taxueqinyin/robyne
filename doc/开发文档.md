# 1. 项目定位（重新定义）

## 1.1 项目目标

`robyne` 第一阶段不是完整播放器。

而是：

# “支持本地播放 + MusicFree 插件运行”的跨平台音频 Runtime Demo

核心验证目标：

* Flutter 多端音频能力
* JS Runtime 稳定性
* MusicFree 插件兼容能力
* 插件 → 搜索 → 解析 → 播放 全链路可行性

---

# 1.2 MVP 成功标准（真正的第一阶段）

只验证以下四件事：

| 能力              | 是否必须 |
| --------------- | ---- |
| 播放本地音频          | 必须   |
| 播放插件解析的在线音频     | 必须   |
| 加载 MusicFree 插件 | 必须   |
| 插件搜索歌曲          | 必须   |

除此之外：

# 一律不做

# 2. 第一阶段架构原则

---

## 原则 1：Backend First

UI 只是调试壳。

所有能力必须：

```text
service → provider → UI
```

禁止：

```text
UI 直接操作业务逻辑
```

---

## 原则 2：MusicFree 是 Adapter，不是核心

项目核心：

```text
Audio Runtime
```

不是：

```text
MusicFree Clone
```

因此：

```text
MusicFree Plugin
↓
Adapter
↓
统一插件协议
↓
robyne Runtime
```

---

## 原则 3：运行时优先于播放器

播放器不是最大风险。

JS Runtime 才是。

开发顺序必须：

```text
JS Runtime
→ Plugin Host
→ Audio
→ UI
```

---

## 原则 4：所有复杂状态收敛到 Service

Riverpod 只负责：

* 状态暴露
* 生命周期管理
* UI 响应

不负责：

* Runtime 调度
* JS 执行
* 播放控制

---

# 4. 第一阶段真正核心：JS Runtime

这是整个项目最大风险点。

必须优先实现。

---

# 4.1 Runtime 定位

第一阶段：

# “受限 JS 执行环境”

不是：

# “安全沙箱”

不要过度承诺安全性。

---

# 4.2 Runtime 目标能力

| 能力           | MVP  |
| ------------ | ---- |
| 执行 JS        | 必须   |
| CommonJS     | 必须   |
| require()    | 必须   |
| Promise 支持   | 必须   |
| axios bridge | 必须   |
| 超时终止         | 尽量   |
| 内存限制         | 暂不强制 |
| 多 runtime 隔离 | 不做   |

---

# 4.3 Runtime 架构（重要）

第一阶段：

# 所有插件共享一个 JS Runtime

原因：

* 降低复杂度
* 降低内存
* 方便调试

但必须预留：

```dart
abstract class PluginRuntime {}
```

以后可以替换。

---

# 4.4 CommonJS 最小实现

仅支持：

```js
module.exports
exports
require()
```

禁止支持：

* npm
* 动态 require
* filesystem

---

# 4.5 require 白名单

仅允许：

| 模块        | 来源     |
| --------- | ------ |
| axios     | bridge |
| cheerio   | assets |
| crypto-js | assets |
| he        | assets |

其他：

```js
throw UnsupportedModuleError
```

---

# 4.6 Runtime 生命周期

```text
App Start
  ↓
Init JS Runtime
  ↓
Inject Builtin Libraries
  ↓
Load Plugins
  ↓
Execute Plugin Methods
```

# 5. 插件系统（重新设计）

---

# 5.1 插件系统定位

插件系统只负责：

```text
加载
调用
生命周期
```

不负责：

* UI
* 状态管理
* 播放

---

# 5.2 插件协议（统一层）

不要直接暴露 MusicFree。

内部统一：

```dart
abstract class MusicSourcePlugin {
  Future<List<Track>> search(String keyword);

  Future<MediaSource> getMediaSource(Track track);

  Future<LyricData?> getLyric(Track track);
}
```

---

# 5.3 MusicFree Adapter

真正兼容 MusicFree 的逻辑：

```text
musicfree_adapter.dart
```

这里负责：

* JS method invoke
* 参数转换
* 返回值映射
* 错误包装

---

# 5.4 插件元信息（必须标准化）

```js
module.exports.meta = {
  id: "netease",
  name: "网易云",
  version: "1.0.0",
  apiVersion: 1
}
```

必须有：

| 字段         | 必须 |
| ---------- | -- |
| id         | 是  |
| name       | 是  |
| version    | 是  |
| apiVersion | 是  |

---

# 5.5 插件生命周期（MVP）

只支持：

```text
load
enable
disable
unload
```

不做：

* hot reload
* update

# 6. 音频系统（MVP 简化）

---

# 6.1 第一阶段目标

只做：

* 单实例播放器
* 单播放队列
* 单音频流

---

# 6.2 不做复杂播放器能力

第一阶段：

| 功能    | 是否做 |
| ----- | --- |
| 播放/暂停 | 做   |
| seek  | 做   |
| 下一首   | 做   |
| 上一首   | 做   |
| 队列    | 做   |
| 顺序播放  | 做   |
| 单曲循环  | 做   |
| 随机播放  | 不做  |

---

# 6.3 Queue Model（重要）

不要：

```dart
List<SongEntity>
```

改成：

```dart
class QueueItem {
  final String queueId;
  final Track track;
}
```

原因：

队列是运行时概念。

不是数据库实体。

---

# 6.4 Track Model（重要）

统一在线/本地歌曲：

```dart
sealed class Track {
  String id;
  String title;
  String artist;
}

class LocalTrack extends Track {}

class RemoteTrack extends Track {
  String pluginId;
}
```

---

# 6.5 Audio URL 不持久化

不要写数据库。

原因：

* 会过期
* 有 token
* 不可靠

播放前：

```text
实时调用 getMediaSource()
```

# 9. Riverpod 使用原则（非常重要）

---

# 9.1 Service 不 Provider 化

不要：

```dart
Provider<JsRuntime>
```

而是：

```dart
final jsRuntime = JsRuntime();
```

然后：

```dart
Provider((ref) => jsRuntime)
```

Provider 只是暴露。

不是管理核心逻辑。

---

# 9.2 UI 只监听 ViewState

不要直接监听 runtime。

# 13. 当前最大风险（必须写进文档）

---

# 风险 1：flutter_js 稳定性

可能：

* crash
* leak
* deadlock

这是最大技术风险。

---

# 风险 2：Windows runtime 兼容

尤其：

* QuickJS
* audio_service

---

# 风险 3：插件兼容性

MusicFree 插件并非严格标准。

不同插件：

* 返回结构不同
* axios 用法不同
* header 不规范

必须允许 Adapter 做兼容修复。

---

# 14. 现在最重要的建议

你现在：

# 不要想着“播放器”

而是：

# 先做一个稳定的插件 Runtime Demo

真正的成功顺序应该是：

```text
JS Runtime 稳定
→ 插件 search 稳定
→ 插件 media source 稳定
→ 音频播放稳定
→ UI
```

因为：

UI 永远是最后的问题。

runtime 才是这个项目真正的生死线。

# Robyne 卡片模式设计规范

## 用途

这份文档是 Robyne 的“卡片模式”默认设计约束。

以后如果用户提到：

- “做成卡片模式”
- “沿用之前那个桌面歌词 UI”
- “整个播放器统一成桌面歌词那种卡片感”

默认按本文档实现，不需要用户再次描述。

## 来源

此风格来源于用户在 2026-07-08 明确认可的桌面歌词卡片 UI。

核心不是“做一张好看的卡片”，而是从第一性原理出发，把播放器当成一个高频操作工具：

- 信息必须一眼可读
- 视觉噪音必须低
- 主信息必须稳定，不允许 hover 后跳位
- 卡片是内容容器，不是装饰物

## 一句话定义

`深色、低反光、低噪音、信息优先、冷静克制的播放器卡片`

## 视觉基调

### 1. 背景

- 背景是深色实体面，不是渐变，不是毛玻璃，不是发光层。
- 默认背景接近：`#1C221F`
- 质感应偏“哑光深色面板”，不要做成纯黑，也不要做成高对比科技蓝紫风。

### 2. 强调色

- 强调色用于歌曲名、关键信息、高亮图标。
- 默认强调色接近：`#9FC9BA`
- 次级强调色接近：`#7CA696`
- 强调色应该是“冷静的染色”，不是霓虹。

### 3. 主文字

- 主内容文字默认纯白或接近纯白：`#FFFFFF`
- 主歌词/主标题权重大、亮度最高。

### 4. 动态取色规则

- 如果存在封面，先提取封面主色。
- 然后用同一色相构建整套卡片颜色，而不是直接把封面颜色原样铺上去。
- 规则：
  - 信息色：保留色相，限制饱和度到中低范围，亮度提到可读区间
  - 背景色：使用同色相，但显著降低亮度和饱和度
  - 次级信息色：在信息色基础上继续降低亮度和饱和度
- 结论上，背景色看起来应像“信息色压暗后的版本”，而不是简单透明度变化。

## 结构规则

### 1. 卡片层级

- 一张卡片只承载一组相关内容。
- 不要卡片套卡片。
- 页面应该由多个平稳的卡片区域组成，而不是一堆悬浮发光块。

### 2. 卡片外形

- 圆角：`16px`
- 边框：1px，低对比度染色边框
- 阴影：默认不用；如果必须用，也只能是极弱阴影，不能形成悬浮感
- 不允许额外外描边、双层描边、发光描边

### 3. 内边距

- 标准卡片内容内边距：
  - 左右：`18px`
  - 上：`14px`
  - 下：`18px`
- 紧凑模式可以略减上边距，但左右和底部要保持稳定，不能导致主内容跳位

## 排版规则

### 1. 信息层级

从上到下应是：

1. 主信息：歌曲名 / 当前主标题
2. 次信息：艺术家、专辑、来源等
3. 主体内容：歌词、主要播放信息、当前核心状态

### 2. 字体气质

- 标题：中等偏粗
- 次级信息：常规字重，明显降低对比度
- 主体内容：最大、最醒目、最稳定

### 3. 对齐

- 元数据默认左对齐
- 主体内容默认居中，除非明确是双排歌词模式
- 双排歌词模式：
  - 当前句左对齐
  - 下一句右对齐
  - 上下两行形成稳定的视觉张力

## 交互规则

### 1. 主内容位置必须稳定

- hover 前后，主歌词或主内容的屏幕位置必须保持稳定。
- 不允许因为出现按钮、背景、标题栏而导致主内容上下跳动或左右漂移。

### 2. hover 只能“揭示”，不能“重排”

- hover 应该显示更多控制和元信息。
- 但 hover 不应该切换成另一套完全不同的布局树。
- 正确做法是：
  - 保持同一个内容骨架
  - 在已有骨架上显示或隐藏辅助层
  - 保证主内容锚点不变

### 3. 可操作范围必须和可见范围一致

- 鼠标 hover / 点击 / 拖动区域必须尽量贴合用户看到的卡片区域。
- 不允许存在大块透明但可触发 hover 的“幽灵区域”。

### 4. 控件行为

- 控件要小、密、明确
- 图标优先，不要用大文字按钮
- 控件应该服务内容，不应抢主视觉

## 适用于整个播放器时的落地方式

如果把整个播放软件改成卡片模式，默认按下面拆： 

- 播放信息区：一张主卡片
- 歌词区：一张主卡片
- 播放控制区：一张紧凑卡片
- 队列 / 列表 / 侧栏：按列表卡片化，但保持密度

不要做成营销页式大留白，也不要堆过多装饰层。

## 禁止项

- 禁止蓝紫渐变科技风
- 禁止大面积玻璃拟态
- 禁止高亮外发光
- 禁止双层描边
- 禁止主内容 hover 后位移
- 禁止按钮出现时把歌词顶下去
- 禁止透明区域比真实可见区域大很多
- 禁止卡片内部再塞一层装饰卡片

## 实现检查清单

实现“卡片模式”时，至少检查以下项目：

- 主背景是否为深色实体面
- 强调色是否冷静克制
- 背景色是否是强调色的压暗版本
- 标题 / 次标题 / 主体内容是否有明确层级
- 卡片是否只有一层边界，没有额外外描边
- hover 前后主内容位置是否完全稳定
- hover 命中区域是否与可见区域匹配
- 控件是否足够紧凑且不抢主内容
- 页面是否避免了卡片套卡片

## 默认设计 token

可直接作为第一版实现：

```text
card.background = #1C221F
card.accent = #9FC9BA
card.accentMuted = #7CA696
card.textPrimary = #FFFFFF
card.radius = 16
card.borderAlpha = 0.24
card.paddingX = 18
card.paddingTop = 14
card.paddingBottom = 18
```

## 给后续 AI 的执行指令

如果用户只说“做成卡片模式”，没有补充说明，默认理解为：

1. 使用本规范
2. 以桌面歌词卡片 UI 为母版
3. 先保证信息结构和主内容稳定，再做视觉细化
4. 禁止擅自引入更花哨的风格替代它
